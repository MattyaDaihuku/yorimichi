## チーム名
チーム8 「Team Loop」

## 背景・課題・解決されること

### **背景・課題：思考を遮る「会話の肥大化」とLLMの物理的限界**
ChatGPTやGeminiなどの対話型AIを利用している際、ある回答（A）の中に気になるトピック（A1, A2...）を見つけ、さらに深掘りしたくなることがあります。しかし、一つのスレッドで深掘りを続けると、以下のような「人間側の不便」と「AI性能の低下」という二重の課題が発生します。

#### **1. ユーザー体験（UX）の悪化**
- **情報の埋没**: 本筋（BやC）に関係のない「寄り道（A1, A2...）」の会話が間に挟まることで、後から必要な情報を探し出したり、前の文脈をさかのぼったりすることが困難になります。
- **思考の断絶**: 深掘りに集中するあまり、当初の目的を忘れてしまう、あるいは履歴が長すぎて見返す気を失ってしまうといった心理的ハードルが生じます。

#### **2. AIモデルの性能劣化（技術的背景）**
最新のAIモデルであっても、一つのスレッドが長大化（ロングコンテキスト化）すると、以下のような物理的な限界に直面します：
- **精度の低下（Context Rot / Attention Dilution）**: コンテキスト長が数万トークンを超えると、モデルが文脈の中間部分の情報を正しく処理できない「Lost in the Middle」現象や、ノイズ増加による回答の不正確さが顕著になります（arXiv:2307.03172 等の論文で報告されています）。
- **応答時間の増大（レイテンシ）**: Transformerモデルの特性上、入力トークン数が増えるほど計算量が増大し、1文字目が出るまでの時間（TTFT）や全体の生成速度が低下します。

### **解決：Gitから着想を得た「思考のフォルダ分け」**
この「人間とAIの両方の限界」を解決するために生まれたのが **yorimichi** です。
Gitの「ブランチ（分岐）」概念をチャットに最適化して導入することで、不必要な履歴をメインスレッドに残さず、文脈を整理された状態（ツリー状）で管理できるようにしました。

これにより、必要な情報を即座に参照できる「さかのぼりやすさ」と、常にAIの性能を最大限に引き出せる「クリアな文脈」を両立しています。

## プロダクト説明
**yorimichi** は、直感的な「思考の分岐」を可能にする次世代AIチャットプラットフォームです。

- **会話の分岐（よりみち）**: 会話の途中から新しいスレッドを派生させ、並列で質問やアイデア出しを行えます。
- **文脈の継承**: 派生したスレッドは、それまでの会話内容（親ブランチの履歴）を完全に理解した状態でスタートします。
- **マージとクリーンアップ**: 並列で行った思考の結果をメインの会話に統合したり、不要になった「寄り道」をサクッと削除したりできます。

「“本当に欲しい”をカタチに」というテーマに対し、AIとの対話を「一直線のやり取り」から「多次元的な思考プロセス」へと進化させることで応えます。

## 操作説明・デモ動画
[デモ動画はこちら（準備中）](https://www.youtube.com/watch?v=fbzGp0XJGq8)

1. **メインチャット**: 通常通りのAIチャットでアイデアを広げます。
2. **ブランチ作成**: 特定の返答から深掘りしたい時、メッセージ横のプラスボタンで新しい「道」を作ります。
3. **並列探索**: 右側に開いたブランチ画面で、自由に質問や試行錯誤を繰り返します。
4. **マージ**: 良い回答やコードが得られたら、「マージボタン」でメインの履歴に成果を反映させます。

## 注力したポイント

### アイデア面
- **Gitの民主化**: 開発者に馴染み深い「分岐管理」の恩恵を、非エンジニアでも「寄り道」という感覚で享受できる仕組みを考案しました。
- **アウトプットの純度**: 試行錯誤のプロセスをブランチに閉じ込めることで、メインスレッドには常に「洗練された結論」だけを残せるようにしました。

### デザイン面
- **Gitを意識させない直感操作**: 「ブランチ」「リベース」といった専門用語を排除。視覚的に「つながり」がわかるノード表現と、スムーズなスプリットウィンドウ表示にこだわりました。
- **モダンでプレミアムなUI**: ダークモードを基調とし、思考を妨げない洗練されたタイポグラフィとアニメーションを採用しました。

### 技術面
- **高度な文脈管理**: Vercel AI SDKとGemini APIを組み合わせ、複雑な分岐構造を持つデータモデル（Prisma / Supabase）との整合性を保ちながら、ストレスのないストリーミング応答を実現しました。
- **柔軟なウィンドウシステム**: 画面幅に合わせて快適にマルチスレッドを表示・操作できるレスポンシブな設計。
