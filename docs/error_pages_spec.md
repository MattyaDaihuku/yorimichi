# エラーページ（404 / 500）仕様書

## 目的
アプリケーション全体で発生するナビゲーションエラー（404）およびサーバーエラー（500）に対して、一貫したユーザー体験、プレミアムなデザイン、および確実な復旧（ホームへの復帰）手順を提供することを目的とします。

## 実装ファイル
- **404 Not Found**: `src/app/not-found.tsx` （グローバル）
- **500 Server Error**: `src/app/error.tsx` （グローバル）

---

## デザイン原則
1.  **視覚的な安心感**: 背景にぼかし効果のあるグラデーションを配置し、不具合が発生してもパニックにならない落ち着いたモダンなデザイン。
2.  **ブランドの一貫性**: 既存の `Sidebar` や `Header` コンポーネントのカラーパレットを継承し、アプリの一部であることを強調。
3.  **アクションの明確化**: 復旧のための主要ボタンを `default`（塗りつぶし）バリアントで目立たせ、迷いなく操作できるように配置。

---

## 機能要件

### 404 Not Found
- **トリガー**: 定義されていないルートへのアクセス、またはデータ取得失敗時の `notFound()` 呼び出し。
- **表示内容**:
  - `Search` アイコンのアニメーション演出。
  - 「ページが見つかりませんでした」というメッセージ。
- **主要アクション**:
  - **ホームに戻る**: `window.location.href` を使用してアプリの状態を完全リセットし、トップページへ強制遷移。

### 500 Server Error
- **トリガー**: アプリケーションランタイム内での例外スロー。
- **表示内容**:
  - `AlertTriangle` アイコンによる警告表示。
  - 「予期せぬエラーが発生しました」というメッセージ。
  - **Error Digest**: デバッグ用にエラー識別子を表示（存在する場合）。
- **主要アクション**:
  - **ホームに戻る**: ストアをクリアし、トップページへ強制遷移。
  - **再試行する**: `reset()` 関数を呼び出し、現在のルートの再レンダリングを試行。

---

## 技術的決定事項と背景
- **ハードナビゲーションの採用**: `next/link` ではなく `window.location.href` を採用しました。これはエラー発生時にクライアント側の状態（ルーターのスタックや Zustand の不正な状態）が復旧の妨げになるケースを完全に排除するためです。
- **Zustand のクリア**: 遷移前に `useChatStore.getState().clearChat()` を実行し、APIエラーなどの以前の状態がトップページに漏れないように保証しています。
- **コンポーネントの再利用**: `Header` を使用し、ページ遷移が起こったことを視覚的に補いつつ、モバイルメニューなどの機能も維持しています。
